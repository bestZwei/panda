# 熊猫烧香趣味桌宠 · 产品文档

版本：**1.2.4**  
更新日期：**2026-11-20**

## 1. 产品概述

### 1.1 一句话定义

一只基于 Electron 的透明桌面熊猫宠物：用经典“熊猫烧香”梗形象做可爱化、可互动、可收集、可轻度恶搞的桌面陪伴玩具。

### 1.2 核心价值

- **怀旧识别度**：还原经典熊猫形象与“三炷香”意象；
- **低门槛互动**：拖动、点击、投喂、聊天都能立刻得到反馈；
- **持续可玩性**：状态、亲密度、宠物等级、成就、签到、签文收藏、小游戏形成长期目标；
- **安全玩梗**：所有“病毒 / 蓝屏 / 关机”效果都是纯视觉动画，不产生真实破坏；
- **本地优先**：数据只存本机，无账号、无云同步、无隐私上报。

### 1.3 目标用户

- 熟悉“熊猫烧香”梗、想轻松怀旧的用户；
- 需要桌面轻度陪伴、想要“活起来”的桌宠爱好者；
- 喜欢成就、签到、收集、小游戏的轻度玩家；
- 想用无伤害彩蛋开玩笑的用户。

### 1.4 非目标

- 不做真实系统管理、杀毒、文件操作或自我复制；
- 不做账号体系、云端同步、跨设备数据；
- 不做强制安装、静默更新或远程控制；
- 不做商业化广告与数据采集。

## 3. 系统架构

### 3.1 进程划分

```text
main.js（主进程）
├── BrowserWindow：桌宠主窗口
├── BrowserWindow：全屏彩蛋窗口（单一 fxWindow 槽位）
├── 拖拽轮询：screen.getCursorScreenPoint()
├── 窗口状态持久化：panda-window.json
├── 全局快捷键：Ctrl+Alt+P/1/2/3/0
├── IPC：设置、彩蛋、截图、更新检查
└── 自测钩子：PANDA_SELFTEST=1

renderer.js（渲染进程）
├── 状态加载、迁移、持久化
├── 交互：点击 / 拖拽投喂 / 聊天 / 游戏
├── 动画调度：待机、心情、主题、彩蛋
├── 音效：Web Audio API 合成
├── UI：工具栏、气泡、菜单、设置、聊天、成长档案、成就墙、关于面板
└── 自测响应：selftest-run
```

### 3.2 DOM 层级

```text
stage
├── pet-root          只按 --ui-scale 缩放
│   ├── pet           熊猫图片 + SVG 叠层 + 点击热区
│   └── pet-meter     香火 / 心情 / 等级经验状态条
└── ui-layer          不缩放，保持文字清晰
    ├── toolbar
    ├── bubble
    ├── fx-layer
    ├── menu
    ├── panel         设置
    ├── chat          聊天
    ├── growth        成长档案
    ├── wall          成就墙
    ├── about         关于与更新
    └── toast
```

### 3.3 关键技术决策

| 决策 | 原因 |
| --- | --- |
| 用 Electron 而非原生 Win32 | 快速实现透明窗口、CSS 动画、SVG、Web Audio 与跨平台 |
| 主进程轮询光标实现拖拽 | 鼠标移出小窗口后 renderer 的 `mousemove` 会停止，主进程轮询更稳定 |
| 图片层和文字层分离缩放 | 缩放后文字仍清晰，工具栏不会随图片放大而漂移 |
| `fullDesktopBounds()` | 多显示器时彩蛋覆盖整个桌面，而非只覆盖主屏 |
| 单一 `fxWindow` 槽位 | 防止多个彩蛋窗口叠加、旧定时器误关新窗口 |
| `localStorage` + JSON 文件 | 状态和设置放渲染层，窗口几何由主进程在窗口创建前读取 |
| HTTPS-only 更新源 | 避免明文 HTTP 清单被篡改；不自动安装代码 |
| 纯视觉彩蛋 | 保证杀毒软件与用户安全边界，不涉及真实恶意行为 |

### 4.2 迁移与容错

`loadState()` 会对旧存档做字段补全与类型校验：

- 数值字段使用 `safeNum` 限制在合法范围；
- 布尔字段使用 `safeBool`；
- 数组和对象字段缺失时回退默认值；
- 聊天历史最多保留 20 轮；
- 旧存档没有 `exp` / `level` 时补为 0 / 1，并根据累计经验重算等级；
- 成就 id 不在定义表中会被忽略；
- 脏 JSON 不会导致应用崩溃。

### 4.3 窗口状态

文件：`userData/panda-window.json`

```json
{ "x": 640, "y": 360, "scale": 1 }
```

启动时会按当前显示器布局校验位置，避免显示器拔掉后桌宠“消失”。

### 4.4 宠物等级设计

等级是累计经验的函数：`level = levelFromExp(exp)`。升级不直接写入截图或软件版本，而是驱动桌宠自身成长。

| 等级 | 累计经验 | 称号 | 解锁效果 |
| --- | --- | --- | --- |
| 1 | 0 | 香火学徒 | 基础互动 |
| 2 | 30 | 闻香小童 | 投喂经验 +1 |
| 3 | 80 | 拜年专员 | 主动搭话概率提升 |
| 4 | 150 | 护香童子 | 签到香火 +2 |
| 5 | 240 | 符咒实习生 | 决策经验 +2，成就“初具道行” |
| 6 | 360 | 香火判官 | 求签经验 +2 |
| 7 | 520 | 熊猫大仙 | 升级回复心情提升 |
| 8 | 720 | 赛博道长 | 聊天经验 +1 |
| 9 | 980 | 香火护法 | 签到经验 +3 |
| 10 | 1300 | 熊猫烧香本体 | 终极称号，成就“香火化身” |

主要经验源：投喂（6~11）、摸头 / 戳肚子（1~2）、聊天（4~5）、求签（5~7）、今日签（8~10）、签到（12~15）、猜拳（4~10）、决策（6~8）、跳舞（3）、变异（5）。

升级奖励：恢复香火 12 点、心情 12 点（7 级后 18 点），播放音效、光效、星星 / 爱心粒子与升级浮字；5 级 / 10 级解锁成就。

## 6. 版本与升级系统

### 6.1 设计目标

- 让用户随时看到当前版本和更新日志；
- 允许维护者配置在线更新源；
- 不在用户不知情的情况下下载或执行代码；
- 无更新源时仍可正常工作。

### 6.2 组成

- `update.json`：本地版本清单；
- 主进程：`get-app-info`、`check-update`、`open-update-url`；
- 渲染层：“关于与更新”面板；
- `CHANGELOG.md`：人类可读版本记录。

### 6.3 更新清单格式

```json
{
  "version": "1.2.4",
  "released": "2026-11-21",
  "feedUrl": "https://example.com/panda-update.json",
  "downloadUrl": "https://example.com/panda-download",
  "notes": ["更新说明一", "更新说明二"]
}
```

字段说明：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `version` | string | 语义化版本号，用于比较 |
| `released` | string | 发布日期 |
| `feedUrl` | string | 远程清单地址，必须 HTTPS；留空则只用本地清单 |
| `downloadUrl` | string | 下载页地址，可为 HTTP 或 HTTPS |
| `notes` | string[] | 更新日志条目 |

### 6.4 行为规则

1. 未配置 `feedUrl`：直接返回“已是最新 / 本地清单”。
2. 配置了 `feedUrl`：HTTPS GET 请求，超时 10 秒，最多 3 次跳转，响应体最大 200 KB。
3. 远程版本高于当前版本：显示“发现新版本”，启用下载按钮。
4. 远程版本不高于当前版本：显示“已是最新版本”。
5. 请求失败：显示错误原因，并回退展示本地日志。
6. 下载按钮只调用系统浏览器打开链接，不下载、不解压、不安装。

### 6.5 安全边界

- 远程清单必须是 HTTPS；
- 版本号解析只取数字段，避免注入；
- 更新日志用 `textContent` 渲染，不解析 HTML；
- 下载链接只允许 http/https；
- 不提供自动替换文件、自动重启或签名验证流程；若未来需要，应配合正式打包与代码签名重新设计。

## 7. 测试与验证

### 7.1 静态检查

```bash
node --check main.js
node --check renderer.js
```

另做 DOM / action 交叉检查：

- 所有 `$('id')` 引用必须在 `index.html` 中存在；
- 所有 `data-action` 必须有对应 `case`；
- CSS 大括号配平；
- JSON 文件可解析。

### 7.2 运行时自测

```bash
PANDA_SELFTEST=1 node launch.js
```

自测会真实执行：

1. 主进程通过 IPC 触发蓝屏并断言窗口在 900ms 后仍存在，随后再打开熊猫暴雨、蓝屏、仿真关机三个全屏彩蛋；
2. 打开聊天、发送消息、验证用户名记忆与历史恢复，并注入 `null` 历史条目验证面板不再崩溃；
3. 触发全部右键动作：三种投喂、求签 / 今日签 / 签到、猜拳、决策、跳舞、三类彩蛋、随机捣乱、惹它生气；
4. 校验设置 / 成就墙 / 聊天 / 关于 / 成长档案之间的面板互斥与 `Esc` 关闭；
5. 打开成长档案，驱动一次 2 级升级与满级升级，校验经验曲线；
6. 切换三种主题与音效开关，验证合成拖拽不会被算作点击、原地点击会被算作点击；
7. 注入损坏存档验证迁移与清洗逻辑（含成就值、重复签文、畸形聊天历史），结束后还原 localStorage；
8. 重复读取今日签，验证当天不会二次发放经验；
9. 检查工具栏 / 气泡居中、聊天回复、版本信息、等级显示、统计与 DOM 状态；
10. 渲染层通过握手消息通知主进程后再开跑，最终输出 `RENDERER SELFTEST: OK` 与 `MAIN SELFTEST: OK` 后自动退出。

### 7.3 为什么需要运行时自测

`syntax check` 与“能启动”无法覆盖只在点击后才执行的代码路径。之前曾出现全屏彩蛋窗口参数错误，启动检查完全通过，但实际触发时抛异常。因此新版功能必须加入自测钩子实际触发。

### 7.4 普通启动验证

```bash
npm start
```

应持续运行；仅出现 Electron 缓存权限或系统证书环境警告属于当前环境噪声，不是应用 JS 错误。

## 8. 风险与边界

| 风险 | 处理方式 |
| --- | --- |
| 被误认为真的病毒 | 所有界面强调视觉玩梗；文档声明无文件修改 / 自复制 / 上报 |
| 彩蛋吓到用户 | 设置提供恶搞模式开关；`Ctrl+Alt+0` 可提前结束 |
| 桌宠丢失到屏幕外 | 启动与缩放时按显示器布局校正位置 |
| 多显示器彩蛋只覆盖主屏 | `fullDesktopBounds()` 取所有 display 的并集 |
| 彩蛋没盖住任务栏 | 创建后同步 `setBounds(fullDesktopBounds())` 覆盖工作区限制；暴雨页用半透明遮罩 |
| 彩蛋无法提前退出 | 主进程注册 `Ctrl+Alt+0`，调用 `closeFxWindow()` |
| 存档损坏 | `loadState()` 容错迁移，脏数据回退默认值 |
| 更新源被篡改 | 强制 HTTPS，不自动安装，只提供下载链接 |
| 动画 DOM 泄漏 | `autoRemove()` 统一回收特效元素 |
| 重复动画互相打断 | 独立 timer 管理跳舞 / 变异 / 待机动画 |

## 10. 维护约定

- 新增功能必须同步更新 `README.md`、`docs/产品说明书.md`、本文档与 `CHANGELOG.md`；
- 版本变更必须同步 `package.json`、`package-lock.json`、`update.json`；
- 涉及新 UI 时必须加入 DOM / action 交叉检查；
- 涉及运行时分支时必须扩展 `PANDA_SELFTEST` 钩子实际触发；
- 任何“升级 / 感染 / 关机”表现都必须保持纯视觉，不触碰真实系统资源。
